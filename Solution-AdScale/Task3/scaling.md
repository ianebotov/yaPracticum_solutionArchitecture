Масштабирование (AdScale)


Цель: выдержать 18 000 RPS (3 мес) → 50 000 RPS (1 год) при P95 ≤ 80 мс.
Текущее состояние: 15 000 RPS, P95 = 110–120 мс (монолит, одна БД).

Вертикальное масштабирование
Ограничения
Вертикальное масштабирование имеет предел, маштабирование ограничено
Стоимость растёт экспоненциально
Поскольку остается один кластер, это единая точка отказа всей системы

Вывод: вертикального маштабирования недостаточно для цели в 50000 RPS через год, использовать его только как временное решение

Горизонтальное масштабирование
Для возможности достежения цели в 50000 PPS, требуется добавиление большего количества реплик
Требования к решению:
Сервисы должны быть независимы
Нагрузка распределяется равномерно
Отказ одной реплики не должен привести к отказу всего

Масштабирование баз данных

PostgreSQL
Read Replicas - реализовать потоковую репликацию для сервиса аналитики
Разделить большие таблицы по данным, дате создания, сделать партиционирование

Kafka
Выделить отдельные топики под разные события(клики, показы, ставки...), это позволит реализовать паралельное получение данных

Redis
Добавление ноды при необходимости
